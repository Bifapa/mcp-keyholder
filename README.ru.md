# MCP Keyholder

[English](README.md) · [Скачать](https://github.com/Bifapa/mcp-keyholder-releases/releases/latest) · [Изменения](CHANGELOG.md) · [Безопасность](SECURITY.md)

Локальное хранилище ключей для AI-агентов. Ключи хранятся зашифрованными. Агенты получают их по MCP только в рамках разрешения, которое вы подтвердили в окне на экране: важные ключи — кодом из приложения-аутентификатора или PIN. Каждое обращение записывается в журнал с подписью.

Внутренние имена остаются прежними: `keyholder.exe`, `kh.exe`, `keyholder-service.exe`, служба `KeyHolder`, каналы `keyholder-*`, папки данных. Так уже настроенные агенты и существующее хранилище продолжают работать.

Подробная концепция и модель угроз — в [CONCEPT.md](CONCEPT.md).

## Что умеет

- **Два режима ядра.** Портативный: ядро работает внутри приложения под вашей учётной записью. Режим службы: ядро — служба Windows под `NT SERVICE\KeyHolder`, база в `%ProgramData%\KeyHolder`, доступ только у службы. Процессы вашего пользователя тогда не читают память ядра и не подменяют файлы.
- Хранилище: мастер-пароль → Argon2id; значения шифруются XChaCha20-Poly1305; политика каждого ключа подписана — правка базы в обход приложения обнаруживается.
- Уровни подтверждения: **Без окна**, **Мягкое** (кнопка), **PIN** (постоянный код), **OTP** (код из приложения-аутентификатора, один код — одно подтверждение), **Запечатан** (агентам никогда — для своих записей: значение любой текст в несколько строк, имя и группа на любом языке).
- Режимы выдачи: **reveal** (значение в ответе MCP) и **env** (`kh run` кладёт ключ в окружение процесса, агент значение не видит).
- Разрешения на сессию агента: только одобренные ключи, на ограниченное время; всё остальное — отказ. Одинаковые повторные запросы склеиваются в один.
- Пресеты разрешений: «Сохранить как пресет» в окне подтверждения, агент просит его через `request_grant({ preset })`.
- **Windows Hello** как альтернатива коду: для уровней «PIN» и «OTP» и для повышения прав присутствие подтверждает системный диалог (на TPM-ключе), подделать его нельзя.
- **Отдельный рабочий стол Windows** для PIN, OTP, мастер-пароля и повышения прав: нативное окно без WebView, экран переключается, код не проходит через интерфейс. В окне — проверенные факты (клиент, процесс), причина «со слов агента», список ключей, срок и анти-фишинговое слово.
- Окно подтверждения в интерфейсе остаётся для уровня «Мягкое» и как обзор запроса; оно исключено из захвата экрана, кнопка активна через 1,5 с.
- Утечки: агент сообщает сам (`report_leak`), KeyHolder ищет значения в тексте (`check_leak`, `kh scan`), выдача в reveal/env помечает ключ как «раскрыт».
- Повышение прав (мастер-пароль + код) для всего, что ослабляет защиту или показывает значение.
- Журнал с HMAC-цепочкой, проверкой целостности и внешним якорем (файл с головой цепочки).
- Смена мастер-пароля, смена анти-фишингового слова, перевыпуск аутентификатора по паролю и коду или по коду восстановления.
- Автоблокировка по бездействию; блокировка при блокировке экрана Windows, уходе в сон и выходе из системы.
- В режиме службы ключи хранилища лежат под DPAPI учётной записи службы, поэтому вход в интерфейс может быть без пароля, по PIN или по OTP; отдельная опция «Полная блокировка» заставляет службу забыть ключи.
- **Перенос хранилища файлом `.mcpkey`**: всё хранилище целиком (ключи, клиенты, настройки, журнал, аутентификатор), зашифровано и открывается мастер-паролем на любом компьютере. «Настройки» → «Перенос хранилища»; на новом компьютере — «Перенести хранилище из файла .mcpkey» на первом экране.
- Массовое редактирование, импорт из `.txt` с выбором фрагментов, светлая и тёмная темы, трей.

- **Работает без интернета.** В сеть ходит только проверка обновлений, и её можно выключить.
- **Обновления с подписью.** Приложение раз в 6 часов проверяет публичный репозиторий релизов. Ставится только установщик, подписанный нашим ключом.

Не вошло (см. план в CONCEPT.md §14): Touch ID и сборка под macOS, режимы `proxy` / `sign` / `recipe`.

## Установка (Windows)

Скачайте `MCP-Keyholder_x.y.z_x64-setup.exe` со [страницы релизов](https://github.com/Bifapa/mcp-keyholder-releases/releases/latest) и запустите. Права администратора не нужны. Дальше приложение обновляется само: «Настройки» → «О программе» → «Проверить обновления».

Из исходников — собрать и установить для текущего пользователя с ярлыком на рабочем столе:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install.ps1
```

Скрипт собирает приложение, `kh.exe` и `keyholder-service.exe` (нужны Rust, Node.js 20+, Visual Studio Build Tools). Хранилище лежит в `%APPDATA%\dev.bifastack.keyholder\vault.db`.

**Режим службы.** «Настройки» → «Режим службы» → «Включить режим службы». Приложение поднимет UAC, установщик перенесёт хранилище в `%ProgramData%\KeyHolder`, поставит службу с автозапуском и закроет доступ к папке для обычных пользователей. После перезапуска приложение работает клиентом службы. Выключение возвращает хранилище обратно.

## Первый запуск

1. Задайте мастер-пароль и анти-фишинговое слово.
2. Отсканируйте QR приложением-аутентификатором (Google Authenticator, Aegis, 1Password…), сохраните коды восстановления, введите код.
3. Добавьте ключи: «Добавить ключ» или «Импорт».

## Подключение агента

«Клиенты» → «Добавить клиента» → подтвердите паролем и кодом. KeyHolder покажет команду для Claude Code:

```bash
claude mcp add keyholder --scope user -e KH_TOKEN=<токен> -- "C:\Users\<вы>\AppData\Local\MCP Keyholder\kh.exe" mcp
```

и JSON для других MCP-клиентов. В режиме службы `kh.exe` лежит в `C:\Program Files\KeyHolder` рядом со службой. Инструменты агента:

| Инструмент | Что делает |
|---|---|
| `list_secrets` | имена, описания, уровни, режимы — без значений |
| `request_grant` | просит доступ к ключам (или к пресету); показывает окно, ждёт решения |
| `my_grants` | активные разрешения сессии |
| `get_secret` | значение ключа в режиме reveal из разрешения |
| `prepare_run` | билет для `kh run` (режим env) |
| `report_leak` | агент сообщает, что ключ засветился |
| `check_leak` | поиск значений ключей в тексте |

## Разработка

```bash
cargo test -p kh-core -p kh-daemon
cd app && npm install && npx tauri dev
```

- `KH_DATA_DIR=<папка>` — запустить приложение на отдельном хранилище (для разработки и тестов). Отладочная сборка с `KH_DATA_DIR` запускается рядом с установленным приложением (без защиты от второго запуска); канал агентов при этом остаётся за установленным.
- `KH_NO_AGENT_PIPE=1` — только в отладочных сборках: не открывать канал агентов (тестовая копия рядом с установленным приложением, скриншоты).
- `KH_SERVICE_CONFIG=<service.json>` — подключить приложение к ядру, которое запущено как `keyholder-service --console`.
- `KH_NO_SECURE_DESKTOP=1` — только в отладочных сборках: не переключать рабочий стол (ввод кода в окне интерфейса). Нужно для автотестов.
- `cargo run -p kh-core --example make_test_vault -- <папка>` — создать тестовое хранилище с известным паролем и примерами ключей.
- `keyholder-service --console --data-dir <папка> [--owner <SID>]` — ядро в режиме службы без установки службы.
- `cargo run -p kh-service --example ui_client -- <SID> [пароль|login] [TOTP-секрет|учётные данные] [имя OTP-ключа]` — headless-проверка канала интерфейса без окон: вход, список ключей, подтверждение запроса агента настоящим кодом.
- Отладочные сборки (`--debug`) не защищают окна от захвата экрана, чтобы можно было делать скриншоты интерфейса. Релизные — защищают.

Структура:

- `crates/kh-core` — хранилище, криптография, TOTP, журнал, поиск утечек, протокол IPC, DPAPI, защита памяти.
- `crates/kh-daemon` — ядро без интерфейса: разрешения, сессии агентов, очередь подтверждений, команды интерфейса (`call(method, params)`), канал агента и канал интерфейса. Один и тот же код работает в приложении и в службе.
- `crates/kh-service` — `keyholder-service`: служба Windows (`install` / `uninstall` / `--console`), ACL на `%ProgramData%`, DPAPI.
- `crates/kh-cli` — `kh`: MCP-сервер по stdio, `kh run`, `kh scan`, `kh status`.
- `app/src-tauri` — приложение: окна, отдельный рабочий стол подтверждения, буфер обмена, импорт, трей, режим службы.
- `app/src` — интерфейс (React + TypeScript).

## Выпуск версии

1. Поднять версию в `Cargo.toml` (workspace), `app/package.json` и `app/src-tauri/tauri.conf.json`, дописать раздел в `CHANGELOG.md`.
2. `powershell -ExecutionPolicy Bypass -File scripts\release.ps1` — собрать и подписать установщик (`target\release\publish`).
3. То же с `-Publish` — выложить релиз в публичный репозиторий `Bifapa/mcp-keyholder-releases` и поставить тег в исходниках.

Ключ подписи обновлений лежит вне репозитория: `%USERPROFILE%\.tauri\mcp-keyholder.key`. Без него новые версии не установятся у пользователей — сохраните копию в надёжном месте.
